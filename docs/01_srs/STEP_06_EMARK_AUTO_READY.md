## ১. মডিউল পরিচিতি ও ব্যবসায়িক উদ্দেশ্য (Introduction & Objectives)

### ১.১ প্রেক্ষাপট
ধাপ ৬ হলো সম্পূর্ণ Denim LACS প্ল্যাটফর্মের **মূল প্রযুক্তিগত হৃৎস্পন্দন (The Core Technological Heartbeat)**। 
২০টি Jeanologia ফ্ল্যাট কনভেয়ার লেজার মেশিনের প্রতিটিতে অপারেটর যখন ট্রলি থেকে কাপড় তুলে টেবিলে বিছিয়ে দেবে, তখন মানুষের কোনো প্রকার মাউস বা কিবোর্ড স্পর্শ ছাড়া **২০০ মিলি-সেকেন্ডেরও কম সময়ে** Jeanologia eMark সফটওয়্যারে ডিজাইনারের অনুমোদিত `.jean5` ফাইলটি সক্রিয় (Auto-Load) করাই এই মডিউলের একমাত্র দায়িত্ব।

### ১.২ মূল উদ্দেশ্য
1. **১০০% টাচলেস অপারেশন (Zero Operator Touch)**: অপারেটরকে eMark-এ কোনো ফাইল ব্রাউজ বা ওপেন করতে হবে না; স্ক্যানার কোড পড়ামাত্র ফাইল নিজে নিজে রেডি হবে।
2. **সাইজ মিক্সিং নিরসন**: ট্রলিতে সাইজ ২৮, ৩০, ৩২, ৩৪ যতই এলোমেলো থাকুক, প্রতি পিসের কিউআর কোড দেখে সফটওয়্যার পলকের মধ্যে ওই নির্দিষ্ট সাইজের ফাইলে সুইচ করবে।
3. **সাব-২০০ms লেটেন্সি বাজেট (Sub-200ms Latency SLA)**: স্ক্যানার 'বিপ' করা থেকে শুরু করে eMark-এর লাল পয়েন্টার আলো জ্বলা পর্যন্ত পুরো প্রসেস ২০০ মিলি-সেকেন্ডের নিচে সম্পন্ন করা।
4. **জিনোলজিয়া আইপিসি সেফটি ও জিরো ক্র্যাশ পলিসি**: Jeanologia মেশিনের নিজস্ব ইন্ডাস্ট্রিয়াল উইন্ডোজ পিসির ওপর কোনো চাপ না ফেলে এজেন্টটি ৩০MB-এর নিচে মেমরিতে চলবে এবং অ্যাটমিক ফাইল রাইটের মাধ্যমে eMark-এর ক্র্যাশ প্রতিরোধ করবে।
5. **১০০% অফলাইন স্থিতিশীলতা**: ফ্যাক্টরির সেন্ট্রাল সার্ভার বা লোকাল ল্যান সাময়িক ড্রপ করলেও মেশিনের লোকাল ক্যাশ থেকে একটানা লেজার প্রসেস সচল রাখা।

## ৪. কার্যকরী রিকোয়ারমেন্টস (Functional Requirements - FR)

### FR-AR-01: আল্ট্রা-ফাস্ট ইউএসবি সিরিয়াল লিসেনার (Scanner Interface)
- এজেন্টটি ব্যাকগ্রাউন্ডে নন-ব্লকিং অ্যাসিনক্রোনাস লুপে ইউএসবি স্ক্যানারের সিরিয়াল বাফার (Virtual COM / HID) মনিটর করবে।
- স্ক্যানার থেকে কোনো কিউআর ডাটা আসবামাত্র এটি কোনো ইউআই ফ্রেম বা থ্রেড ব্লক না করে তৎক্ষণাৎ ইভেন্ট ট্রিগার করবে।

### FR-AR-02: ইন-মেমরি ডোমেন ভ্যালিডেশন ও সিকিউরিটি চেক
- স্ক্যান হওয়া টেক্সটকে তাত্ক্ষণিক রেজেক্স ভ্যালিডেশন করবে:
  `^LACS\|PO[A-Za-z0-9_-]+\|ST[A-Za-z0-9_-]+\|SZ[0-9]+\|...$`
- যদি কাপড়টি ধাপ ৫-এ আনুষ্ঠানিকভাবে লেজারে রিসিভ না হয়ে থাকে (`current_status != INTAKE_AT_LASER`), তবে এজেন্ট ফাইল লোড ব্লক করবে এবং স্ক্রিনে বড় লাল সতর্কতা দেবে:  
  *🛑 "SECURITY ALERT: Garment Not Received at Laser Intake!"*

### FR-AR-03: লোকাল ক্যাশ লুকআপ ও অ্যাটমিক হটফোল্ডার রাইটার (Atomic Dispatcher)
- এজেন্ট সার্ভারের নেটওয়ার্ক কলের জন্য অপেক্ষা করবে না।
- অনুমোদিত ফাইলগুলো আগেই এজেন্টের লোকাল ড্রাইভে (`C:\Jeanologia_Agent\cache\`) সিঙ্ক করা থাকবে।
- **অ্যাটমিক রাইট নীতি**: eMark-এর সক্রিয় ফোল্ডারে সরাসরি রাইট করা নিষিদ্ধ। 
  1. এজেন্ট প্রথমে একটি অস্থায়ী ফাইল তৈরি করবে: `C:\Jeanologia\Jobs\active.tmp`
  2. ডেটা রাইট শেষে ডিস্কে ফ্লাশ (`os.fsync`) করবে।
  3. এরপর মিলি-সেকেন্ডে ফাইলটি রিনেম করবে: `active.jean5`।
  *কেন?* এর ফলে Jeanologia eMark কখনো অর্ধেক লেখা বা অসম্পূর্ণ ফাইল রিড করে ক্র্যাশ করবে না।

### FR-AR-04: জিনোলজিয়া eMark রেড-পয়েন্টার প্রজেকশন ট্রিগার
- ফাইলটি eMark-এ লোড হওয়ামাত্র লেজার মেশিনের লাল গাইডিং আলো (Red Pointer Frame / Contour Box) কাপড়ের ওপর ফ্রন্ট হুইস্কারের পজিশন প্রজেক্ট করবে।
- অপারেটর চোখের দেখায় বুঝতে পারবে কাপড়টি টেবিলে সোজা ও সঠিক স্থানে বসেছে।

### FR-AR-05: কমপ্লিট বডি স্মার্ট ফ্রন্ট-টু-ব্যাক ফ্লিপ সিকোয়েন্সার (Front ➔ Back)
- ৮০-৯০% সম্পূর্ণ প্যান্টের ক্ষেত্রে এটি একটি ২-ধাপের চক্র:
  * **ধাপ ক (Front Pass)**: কিউআর স্ক্যান করলেই প্রথমে লোড হবে `Size_32_Front.jean5`। অপারেটর প্যাডেল চেপে ফ্রন্ট লেজার শেষ করবে।
  * **ধাপ খ (Back Pass)**: ফ্রন্ট লেজার ফায়ার শেষ হওয়ামাত্র (লেজার সাইকেল কমপ্লিশন সিগন্যাল) এজেন্ট স্ক্রিনে দেখাবে: **[ FLIP TO BACK ]**। অপারেটর প্যান্ট উল্টে দিলে ফুট-সুইচ বা কনভেয়ার ট্রানজিটের সাথে সাথে eMark-এ স্বয়ংক্রিয়ভাবে `Size_32_Back.jean5` লোড হয়ে যাবে।
  * অপারেটরকে দ্বিতীয়বার কিউআর স্ক্যান করতে হবে না।

### FR-AR-06: কাটিং পার্টস সিঙ্গল-পাস ফাস্ট ডিসপ্যাচ (Cut Panels - ১০-২০%)
- কাটিং পার্টসের ক্ষেত্রে (যেমন: পকেট) কোনো ফ্রন্ট/ব্যাক টগল থাকবে না।
- কিউআর কোড দেখেই এজেন্ট বুঝবে এটি `CUT_PANEL` এবং সাথে সাথে নির্দিষ্ট কম্পোনেন্ট ফাইল (যেমন: `Pocket_Left.jean5`) লোড করবে। কনভেয়ার অবিরাম গতিতে চলতে থাকবে।

### FR-AR-07: অফলাইন রেসকিউ মোড (Local Fault-Tolerant Engine)
- কোনো কারণে লোকাল ল্যান কেবল ডিসকানেক্ট হলেও Jeanologia মেশিনে লেজার কাজ ১ সেকেন্ডের জন্যও থামবে না।
- এজেন্টের লোকাল ক্যাশে আগের সব অনুমোদিত স্টাইলের ফাইল সংরক্ষিত থাকে।
- স্ক্যান ইভেন্টটি এজেন্টের নিজস্ব লোকাল `sqlite3` ডেটাবেজে জমা থাকবে। ল্যান ফিরে আসলে ব্যাকগ্রাউন্ড থ্রেড সার্ভারের সাথে ডাটা সিঙ্ক করে নেবে।

### FR-AR-08: ফলব্যাক বিকল্প (Emergency Fallback Controls)
- যদি কোনো কারণে কাপড়ের কিউআর লেবেল ছিঁড়ে যায় বা স্ক্যানার ড্রপ করে:
  * **বিকল্প ১ (টাচ স্ক্রিন বাটন)**: অপারেটর মেশিনের স্ক্রিনে বড় বড় বাটন থেকে সাইজ সিলেক্ট করতে পারবে (`[ ২৮ ] [ ৩০ ] [ ৩২ ] [ ৩৪ ]`)।
  * **বিকল্প ২ (টেবিল বারকোড কার্ড)**: টেবিলে লাগানো লেমিনেটিং কার্ডের সাইজ ৩২ বারকোডে হ্যান্ডহেল্ড স্ক্যানার দিয়ে 'বিপ' করলে সাথে সাথে ফাইল লোড হবে।

## ৫. অকার্যকরী রিকোয়ারমেন্টস (Non-Functional Requirements - NFR)

### NFR-AR-01: মেমরি ও সিপিইউ ইউটিলাইজেশন গার্ড
- `laser_agent.exe` ব্যাকগ্রাউন্ড উইন্ডোজ সার্ভিসের মেমরি ব্যবহার কোনো অবস্থাতেই **৩০ মেগাবাইটের বেশি হতে পারবে না**।

## ৭. ডেটাবেজ স্কিমা স্পেসিফিকেশন (Database Schema for Step 6)

### টেবিল ১: `laser_machines` (২০টি মেশিনের সেন্ট্রাল প্রোফাইল)
```sql
CREATE TABLE laser_machines (
    id UUID PRIMARY KEY, -- RFC 9562 UUIDv7
    machine_code VARCHAR(50) NOT NULL UNIQUE, -- MACHINE_01, MACHINE_07 ইত্যাদি
    machine_model VARCHAR(100) DEFAULT 'Jeanologia Flat Conveyor',
    table_type VARCHAR(50) DEFAULT 'FLAT_CONVEYOR', -- FLAT_CONVEYOR, MANNEQUIN
    ip_address VARCHAR(50) NOT NULL,
    emark_version VARCHAR(50) DEFAULT 'eMark 5.x',
    current_status VARCHAR(30) DEFAULT 'IDLE', -- IDLE, RUNNING, ERROR, OFFLINE
    last_heartbeat TIMESTAMPTZ,
    total_lifetime_pieces BIGINT DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    is_deleted BOOLEAN DEFAULT FALSE
);
CREATE INDEX idx_laser_machines_code ON laser_machines(machine_code);
```

### টেবিল ২: `active_table_jobs` (টেবিলে রানিং লাইভ পিস ট্র্যাকিং)
```sql
CREATE TABLE active_table_jobs (
    id UUID PRIMARY KEY, -- RFC 9562 UUIDv7
    machine_id UUID NOT NULL REFERENCES laser_machines(id) ON DELETE CASCADE,
    garment_unit_id UUID NOT NULL REFERENCES garment_units(id) ON DELETE RESTRICT,
    active_part VARCHAR(30) NOT NULL, -- FRONT_BODY, BACK_BODY, CUT_PANEL
    recipe_file_id UUID NOT NULL REFERENCES laser_recipe_files(id) ON DELETE RESTRICT,
    scanned_at TIMESTAMPTZ DEFAULT NOW(),
    front_laser_start TIMESTAMPTZ,
    front_laser_end TIMESTAMPTZ,
    back_laser_start TIMESTAMPTZ,
    back_laser_end TIMESTAMPTZ,
    is_completed BOOLEAN DEFAULT FALSE
);
CREATE INDEX idx_active_table_machine ON active_table_jobs(machine_id);
```
